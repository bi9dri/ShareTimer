# ADR 0004: 管理者トークンを localStorage に保存する

- 日付: 2026-10-10
- 状態: 承認済み

## 文脈

ユーザ管理を行わないため、作成端末を「管理者」として識別する仕組みが要る。候補は (a) 管理者専用 URL に秘密トークンを含める、(b) localStorage にトークンを持つ、(c) 認証なし。

## 決定

- セッション作成時に `crypto.getRandomValues(new Uint8Array(32))` を base64url 化したトークンを発行し、作成応答でのみ返す。サーバは SHA-256 ハッシュのみ保存する。
- 作成端末はトークンを `localStorage` に保存する。
- 管理操作は `Authorization: Bearer <adminToken>` で認可する。
- セッション URL は管理者・ユーザ共通。トークンを URL に含めない。
- ハッシュ照合は定数時間比較（`crypto.subtle.timingSafeEqual`）で行う。

## 影響

- 良い: トークンが URL・サーバログ・Referer に漏れない。URL を共有しても管理権限は渡らない。
- 良い: 同一端末ならリロードやタブ再訪で管理権限が維持される。
- 悪い: localStorage を消す / 別端末を使うと管理権限を失い、復旧手段がない（トークン再発行は非目標）。
- 悪い: XSS が成立するとトークンを窃取され得る。対策として静的配信のみ・入力のエスケープを徹底する。

# ADR 0005: Cloudflare Workers + Durable Objects で配信する

- 日付: 2026-10-10
- 状態: 承認済み

## 文脈

非営利アプリのため低コスト・無料が望ましい。一方で (a) セッション状態のデプロイ時永続化、(b) 水平スケール を要件に加えたい。利用量は未知数で、特定セッションが 24 時間継続視聴される可能性も排除できない。

## 決定

配信基盤を **Cloudflare Workers + Durable Objects（SQLite バックエンド）** とする。

- **1 セッション = 1 Durable Object**。Worker が `idFromName(sessionId)` で対象 DO にルーティングする。セッションごとに自動シャーディングされ、セッション間の調整は不要。
- 状態は **DO の SQLite storage** に保存。hibernation やデプロイをまたいで永続する。
- 期限切れ・TTL 削除は **DO Alarms** で行う（[ADR 0001](0001-realtime-websocket-rest.md)）。永続で、休止中でも発火する。
- 配信は **WebSocket Hibernation API**。更新が無い間は DO が休止し、duration 課金が止まる。死活監視はクライアントの `ping` にエッジが `setWebSocketAutoResponse` で `pong` を返す方式にし、DO を起こさない。
- 静的フロント（HTML/CSS/JS）は **Cloudflare Pages** から配信する（静的配信は無料で、DO の課金対象を消費しない）。
- **Supabase は採用しない**。Free プランは 7 日間の無トラフィックでプロジェクトが自動停止し、低トラフィックの非営利アプリでは可用性の担保にならない。Realtime の同時接続枠（Free 200）も、24/7 のリアルタイム配信には DO 単体のほうが安く堅い。
- **インメモリ・単一インスタンスは採用しない**。永続化と水平スケールの要件を満たさないため（検討時の設計は採用に至っていない）。
- **更新（[ADR 0008](0008-ogp-absolute-urls-at-the-edge.md)）**: 静的フロントは Cloudflare Pages ではなく Workers の Static Assets から配信する。

## コスト試算（2026年・公式の課金モデル）

Workers と Durable Objects は**別々の課金枠**を持つ（混同しやすい）。

| 区分 | Free | Paid |
|---|---|---|
| Workers リクエスト | 100,000/日 | $5/月（最低額）・10M/月込み + $0.30/M |
| DO リクエスト | 100,000/日 | 1M/月込み + $0.15/M |
| DO duration | 13,000 GB-s/日 | 400,000 GB-s/月込み + $12.50/M GB-s |
| DO SQLite 行読み / 行書き | 5M/日 / 100k/日 | 25B/月込み / 50M/月込み |
| DO ストレージ | 5 GB | 5 GB-month 込み + $0.20/GB-month |

前提:

- 1 つの論理操作（作成・WS 接続・管理操作など）= **Worker 1 req + DO 1 req**（各バケットに同数）。
- DO は常に 128 MB（= 0.125 GB）で duration 計上。**hibernation 中は 0**（起床処理の ms のみ）。
- WS 送信は無料、受信は 20:1、`setWebSocketAutoResponse` の自動応答は課金対象外。アラーム = DO req 1、`setAlarm` = 行書き 1。
- ブロードキャスト（送信）とクライアントの定期 `ping`/自動 `pong` は無視できる。

1 セッションあたりの論理操作:

| プロファイル | 内訳 | 操作/セッション |
|---|---|---|
| 軽量 | 作成 1・接続 3・再接続 3・操作 20・期限 1・TTL 1 | 約 29 |
| 標準 | 作成 1・接続 10・再接続 60・操作 100・期限 1・TTL 1 | 約 173 |

| シナリオ | セッション/日 | 操作/日（各バケット） | 判定 |
|---|---|---|---|
| 小規模（軽量） | 100 | 2,900 | 無料枠内 |
| 中規模（標準） | 1,000 | 173,000 | Paid 約 **$5.6/月** |
| 大規模（標準） | 5,000 | 865,000 | Paid 約 **$13.5/月** |

- 無料枠の分岐点は軽量で**約 3,400 セッション/日**、標準で約 580/日（Worker・DO とも 100k/日で足切り）。
- Paid 内訳（1,000 標準/日 = 5.19M/月）: Workers は込み 10M 内で $0、DO は (5.19M − 1M) × $0.15 ≒ $0.63。最低額 $5 と合わせ **約 $5.6/月**。
- 大規模（5,000 標準/日 = 25.95M/月）: Workers (25.95M − 10M) × $0.30 ≒ $4.8、DO (25.95M − 1M) × $0.15 ≒ $3.7。$5 と合わせ **約 $13.5/月**。
- **duration・SQLite・storage は全シナリオで余裕**（duration は起床処理の ms のみ、storage は 24h で消えるため定常で数 MB、行書きはセッションあたり数回）。
- Free は超過時に**課金ではなくエラー**になる（青天井にならない）。

## 影響

- 良い: 外部ストア（Redis 等）を持たずに永続化と水平スケールを両立。構成が単純。
- 良い: hibernation により、利用が間欠的なら無料枠に収まる。利用が伸びても月 $5〜14 規模。
- 良い: DO は単一スレッド実行のため状態更新が直列化され、競合が起きない。
- 悪い: Workers ランタイムは Node.js ではない（Web 標準 API + Cloudflare 固有 API）。フロント/バックは TypeScript のままだが、Node 依存のライブラリは使えない。
- 悪い: DO の hibernation では in-memory が消えるため、状態は常に storage 経由で復元する実装が要る。
- 注意: 無料枠超過は失敗として現れる。監視して早めに Paid（$5/月）へ移す。

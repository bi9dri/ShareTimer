# ADR 0003: アラームは全端末がローカルに判定・再生・停止する

- 日付: 2026-10-10
- 状態: 承認済み

## 文脈

タイムアウト時、共有タイマーの目的上すべての端末が鳴るべき。鳴らす時刻をサーバの配信タイミングに委ねると、配信遅延のぶん端末ごとにバラつく。止める操作の主体、音量、そして「可能な限り厳密に同時に鳴る」ことの実現方法を決める必要がある。

## 決定

### 配信モデル

- アラームは**全端末**が鳴らす。各端末が [ADR 0002](0002-absolute-endsat-ntp-sync.md) の補正済み残り時間が 0 に達した時点で、プリセット音源を**1 回**再生する。サーバの期限切れ配信は待たない。
- 停止は**各端末がローカルに**行う。サーバはアラームの再生・停止状態を管理しない。
- **音量**は各端末がローカルに操作する（localStorage）。サーバへ送らない。
- 多重再生防止のため、端末は「このタイマー世代で再生済み」フラグを持つ。`endsAt` が変わると世代をリセットする。
- 期限切れ後に接続してきた端末は、初回状態が `expired` でも鳴らさない（`running` から期限切れへの遷移を見た端末だけが鳴らす）。

### 同時性を最優先にする

失敗要因は 2 つ。時計オフセットの推定誤差は [ADR 0002](0002-absolute-endsat-ntp-sync.md) の NTP 推定で解消する。もう一つの音声再生の起動遅延に対して:

- `HTMLAudioElement.play()`（呼び出しから発音まで可変の遅延）ではなく **Web Audio API** を使い、`AudioContext` の高精度クロック上に目標時刻をスケジュールする（`src.start(ctx.currentTime + delay)`）。`setTimeout` の粒度や `play()` の揺らぎに依存しない。音源は事前に `decodeAudioData` して常備する。
- 端末ごとの音声出力遅延は `AudioContext.outputLatency` / `baseLatency` で補正する。実機依存で机上値では合わないため、**手動キャリブレーション値**を端末ローカル設定に用意する。
- 期限直前に `offset` を再同期する（[ADR 0002](0002-absolute-endsat-ntp-sync.md)）。
- ブラウザの自動再生制限により、入室時に無音で `AudioContext` を `resume()` して unlock する。

目標は端末間で数十 ms 以内。下限は物理的（`offset` 推定誤差 ≒ RTT/2 と音声出力遅延の差）で、共通クロック（GPS/PTP 相当）が無いブラウザでは原理的にこれ以上は困難。

## 影響

- 良い: サーバの配信タイミングに依存せず、正確な時刻に鳴る。停止もローカルなので他端末に影響しない。
- 良い: サーバに精密なタイマーが不要（DO Alarm はスナップショットの一貫性のためだけに存在）。
- 悪い: 端末側にオフセット推定・Web Audio スケジューリングの実装が要る。`<audio>` を 1 回 `play()` するより複雑。
- 悪い: 期限切れの瞬間に接続していない端末はアラームを逃す。許容（「鳴りっぱなし」モードが必要になれば別途追加）。
- 悪い: ハードウェア差で完全な同時性は消えない。キャリブレーションで低減する。
- 注意: 音源は事前デコード必須。デコードが期限に間に合わないと最初の一発を逃す。

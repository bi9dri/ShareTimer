# ADR 0008: OGP の絶対 URL を Worker で埋める

- 日付: 2026-10-27
- 状態: 承認済み
- 関連: [ADR 0005](0005-cloudflare-durable-objects-hosting.md)

## 文脈

OGP と canonical は絶対 URL を要求する。一方で配信ホストはデプロイ時まで確定しない（`*.workers.dev` か独自ドメインか、プレビュー環境も含む）。ビルド時に固定すると、環境ごとに成果物を作り分けるか、本番以外で誤った URL を配信することになる。

静的アセットは、リクエストがアセットと一致すると Worker を通らずに返る。`/` は `index.html` と一致するため、そのままでは HTML を書き換えられない。`/s/:id` のようなクライアント側ルートはアセットに一致しないので、Worker が返す。

## 決定

- `index.html` に `{{ORIGIN}}` / `{{PATH}}` / `{{QUERY}}` を置き、Worker が `url.origin` / `pathname` / `search` で埋める。属性値に入るため HTML エスケープする。
- 置換は `replaceAll` に**関数**を渡す。置換文字列を渡すと URL 中の `$&` や `` $` `` が置換パターンとして解釈され、プレースホルダが残る。
- canonical はクエリを含めない。クエリで変わる画面は無く、トラッキング用の値が別 URL として索引されるのを避ける。`og:url` は共有された URL をそのまま指す。
- `/` だけを `run_worker_first` で Worker に先に通す。他のルートはアセットに一致しなければ Worker に来るため、設定を増やさない。
- `etag` は書き換え後の HTML から計算し直し（SHA-256）、`If-None-Match` が一致すれば 304 を返す。アセットの etag は書き換え前のバイト列を指すため引き継がない（RFC 9110 のとおり、URL の内容が変わればバリデータも作り直す）。
- 書き換えで本文の長さと符号化が変わるため、`content-length` / `content-encoding` は引き継がない。HEAD は本文を持たず GET の表現と対応しないので、バリデータを付けない。
- OGP の内容はサイト共通とする。セッション個別の残り時間は出さない。

## 影響

- 良い: どのホストで配信しても OGP と canonical が正しい絶対 URL になる。ドメインを設定に持たなくてよい。
- 良い: 再訪時は 304 になり、数 KB の HTML を再送しない。
- 良い: 静的アセット（画像・音源）は従来どおり Worker を通らない。課金と遅延への影響は `/` のアクセスに限られる。
- 悪い: `/` と `/s/:id` の HTML はリクエストごとに書き換えるため、エッジキャッシュに乗せにくい（数 KB のため実害は小さい）。
- 悪い: セッション個別の OGP を出すには、クロールごとに DO を読むことになり、コストと結合が増える。
- 注意: `index.html` を Worker を通さず配信すると、プレースホルダが未置換のまま出る。HTML を返すルートを増やすときは `run_worker_first` も更新する。

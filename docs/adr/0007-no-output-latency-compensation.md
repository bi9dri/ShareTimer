# ADR 0007: アラームの出力遅延補正を廃止する

- 日付: 2026-10-19
- 状態: 承認済み
- 関連: [ADR 0003](0003-client-side-alarm.md)

## 文脈

ADR 0003 は、音が「耳に届く時刻」を端末間で揃えるため、`AudioContext.outputLatency`（と `baseLatency`）のぶんだけ開始時刻を前倒ししていた（`delay = remaining - outputLatency`）。

しかし `outputLatency` は仕様上「推定値」であり、環境によって大きく外れる。実測では、`outputLatency` が約 0.9 秒と報告された環境があり、そのぶんアラームが期限より 0.9 秒早く鳴った。ブラウザだけで真の出力遅延を正確に測る API は無く、音響ループバック（クリック音＋マイク）以外に実測手段は無いが、マイク権限と静かな環境が必要で端末ごとの再測定も要るため採用しない。

## 決定

- 出力遅延の補正を**廃止**する。`start()` は期限ちょうどの時刻にスケジュールする（`delay = remaining`）。
- `AlarmPlayer.outputLatencyMs()` を削除する。代わりに手動キャリブレーション値も設けない。
- 音響ループバックによる実測は行わない。

## 影響

- 良い: 表示が 00:00 になった瞬間に音が鳴り始める。端末の報告値に左右されず、挙動が予測できる。
- 良い: 実装が単純になり、誤った推定値による大きなずれが原理的に起きない。
- 悪い: 端末間で「音が届く時刻」は各端末の実出力遅延だけずれる（有線で数十 ms、Bluetooth で百数十 ms）。同時性は物理的な下限までしか揃わない。
- 注意: `outputLatency` を参照しないため、デバイスを問わず同じ挙動になる。

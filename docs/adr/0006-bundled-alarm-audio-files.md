# ADR 0006: アラーム音源は合成ではなく同梱の音声ファイルにする

- 日付: 2026-10-19
- 状態: 承認済み

## 文脈

[ADR 0003](0003-client-side-alarm.md) は再生方式（Web Audio のスケジューリング）を決めたが、音源そのものは「プリセット音源」とだけ定め、実際の音は実装時に確定するとしてきた。当初は `OscillatorNode` による合成 3 種（`beep` / `chime` / `bell`）で仮実装していた。

ローカルで動く音声生成（Stable Audio 3 / audio-studio-mcp）でアラーム音をデザインできるようになったため、合成の矩形波ではなく実際に作った音をプリセットとして使いたい。

## 決定

- 音源は**同梱の音声ファイル**（`public/alarm/*.wav`）とする。合成はしない。
- 形式は **WAV 16-bit / 44.1 kHz / ステレオ**。Ogg Vorbis はサイズで大きく勝るが、iOS Safari が `decodeAudioData` で Ogg Vorbis を扱えず、複数端末で鳴ることが前提の本アプリでは致命的なので採用しない。
- プリセットは 4 つ。ID は `alarm` / `bell` / `piano` / `jingle`、既定は `alarm`。
- 合成時代の `beep` / `chime` / `bell` は**置換**する（後方互換は持たない）。セッション TTL は 24 時間なので、旧 ID が残る影響は最大 24 時間に収まる。
- 再生は ADR 0003 の方式を維持する。`OscillatorNode` を `AudioBufferSourceNode` に置き換えるだけで、`start(when)` による同期の仕組みは変えない。
- デコード済みバッファは**起動時に全プリセット分**を `fetch` + `decodeAudioData` して常備する。取得に失敗したプリセットは無音になる（合成フォールバックは持たない）。

## 影響

- 良い: 実際に音をデザインして選べる。合成の矩形波より明確に良い音になる。
- 良い: 読み込みが起動時なので、期限直前にデコードを待つ事態（ADR 0003 が警告していた失敗）を避けられる。
- 良い: 形式・ビット深度だけを変えて同梱でき、生成物そのものの音色を保てる。
- 悪い: リポジトリにバイナリを抱える（4 音で約 1.5 MB）。「音声ファイルを持たない」という当初の方針を反転させる。
- 悪い: 音源の差し替えには再ビルドが要る。管理画面の操作だけでプリセットを増やすことはできない。
- 注意: `alarmSound` の ID を変えたため、旧 ID を持つ既存セッションでは選択肢が一致しない（TTL 24 時間で解消）。
- 注意: WAV は非圧縮なので、プリセットを増やすほど配信量が増える。増やすなら形式の再検討が必要。
- 注意: 音量は端末ローカル設定のまま（ADR 0003）。音源側は -14 LUFS で揃えてあり、プリセット間のラウドネス差は小さい。
